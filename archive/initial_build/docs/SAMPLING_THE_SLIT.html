Sampling the Slit

For a single window on the detector, four flags — g_ratio, state_interp, anchor_density, and which solve (coarse / hires) — decide two different grids: where the state's own unknowns live, and where the forward model actually runs radiative transfer. This is what each one changes.

real detector pixel bin centre — state's own point anchor — hi-res render point true geometry (GD polynomial, exact) nearest-neighbour assignment free (retrieved) frozen (held at prior)

01Coarse vs. hires, for one window

Keystone and smile mean a detector row's own along-slit position (η) is not evenly spaced with its neighbours — some rows crowd into a narrow η range, others spread out. Both solves see the identical real pixels and the identical true geometry (the upper half of each panel below is the same). They differ only in where radiative transfer gets evaluated — the lower half.

02state_interp — only hires has a choice to make

Coarse's anchor grid is the state's own bin_centers, so interpolating the state onto itself is the identity — the flag has nothing to act on there. For hires, every anchor needs a value the state doesn't have directly, and there are two ways to get one for a row that isn't currently being retrieved.

03anchor_density — how fine the render grid gets

Independent of both of the above: anchor_density only sets how many anchors exist per detector row within the padded window. It doesn't touch G (the unknowns) or which rule state_interp applies — it just makes the hires rendering grid finer or coarser.

g_ratio → G unknowns per window (the state's own resolution) — and, for coarse only, the render grid itself, since they're the same points hires' anchor grid, which is set by anchor_density independently more free elements → bigger GN solve

state_interp how a frozen row gets its anchor value (interpolated vs. exact truth) — hires only coarse (no-op); free rows (always interpolated either way) no extra RT calls

A fourth axis in the current regression matrix — jacobian_used (fd vs. analytic) — doesn't touch any grid at all; it only changes how the Gauss-Newton step gets its derivatives once both grids above are already fixed. That's why the 8-config matrix (co2/co2p × 58/29 windows × g_ratio 1/3) varies G and window count, always with state_interp=True and anchor_density=1 held fixed — it's deliberately probing the first two knobs on this page, one at a time, against a solver choice that shouldn't move the answer at all.
